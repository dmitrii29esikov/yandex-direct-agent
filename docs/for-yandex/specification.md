# Спецификация приложения

**Название:** Yandex Direct Agent
**application_id:** 3f7692ca2f18447aaf983b5514a96f1f
**Платформа:** веб-сервисы (OAuth), локальный MCP-сервер
**Язык:** Python 3.14
**Протокол обмена:** JSON (API Яндекс.Директа v5)
**Версия библиотек:** requests 2.34.2, python-dotenv 1.2.3, mcp 1.30.0, openpyxl 3.1.5, pandas 3.0.5, xlrd 2.0.2

## 1. Назначение

Внутренний инструмент для аудита и управления рекламными кампаниями
Яндекс.Директа. Работает в связке с ИИ-агентом: агент вызывает методы
приложения как инструменты и на основе полученных данных формирует
рекомендации. Приложение не является публичным сервисом и не
предоставляется сторонним пользователям — используется владельцем и
специалистом, обслуживающим аккаунт партнёра.

## 2. Основные функции

1. **Получение статистики и отчётов.** Кампании, группы, объявления, ключевые
   фразы; отчёты по показам, кликам, CTR, CPC, расходу, конверсиям и цене
   конверсии за произвольный период.
2. **Управление кампаниями и объявлениями.** Изменение текстов объявлений
   (в пределах лимитов Директа) и дневного бюджета кампаний.
3. **Автоматический аудит.** Проверка аккаунта по 29 правилам: структура
   кампаний и групп, длины и оформление текстов, модерация, бюджет и ставки,
   качество данных Метрики, состояние разметки Тег Менеджера, связки между
   тремя контурами.
4. **Формирование рекомендаций.** Найденные проблемы группируются в диагнозы
   с оценкой приоритета, описанием последствий и порядком действий.

## 3. Схема взаимодействия с Директом

```
Пользователь
     |
     v
ИИ-агент (Chatbox / Cursor)
     |
     |  вызов инструмента: имя инструмента + параметры
     v
MCP-сервер приложения (Python, локально)
     |
     |  HTTPS, POST, JSON, Authorization: Bearer <OAuth-токен>
     v
API Яндекс.Директа v5 (api.direct.yandex.com/json/v5/<сервис>)
     |
     |  JSON-ответ
     v
MCP-сервер -> ИИ-агент -> пользователь (отчёт, рекомендации)
```

Используемые сервисы API v5:

| Сервис | Назначение | Режим |
|---|---|---|
| `campaigns` | Список и параметры кампаний; обновление дневного бюджета | чтение + запись |
| `adgroups` | Группы объявлений | чтение |
| `ads` | Объявления, их тексты и статусы; обновление текстов | чтение + запись |
| `keywords` | Ключевые фразы | чтение |
| `clients` | Параметры рекламодателя | чтение |
| `reports` | Отчёты по эффективности за период (Reports API) | чтение |

## 4. Авторизация

- Протокол OAuth 2.0 Яндекс.ID. Токен выдаётся по схеме
  `response_type=token`, передаётся в заголовке `Authorization: Bearer`.
- Токен выпускается **отдельно на каждый обслуживаемый аккаунт** и
  хранится локально в файле, исключённом из системы контроля версий.
  Токены не передаются третьим лицам и не публикуются.
- Права приложения: **Яндекс.Директ**, **Яндекс.Метрика**.
- Для аккаунтов, доступ к которым предоставлен по агентской схеме,
  предусмотрен режим с заголовком `Client-Login` и расходованием баллов
  агентства (`Use-Operator-Units`).

## 5. Что приложение НЕ делает

Перечислено явно, чтобы не создавать ложных ожиданий:

- не управляет ставками и не участвует в аукционе (биддинга нет);
- не использует сервис подбора ключевых слов (Wordstat) и не добавляет
  новые ключевые фразы;
- не создаёт и не удаляет кампании, группы и объявления;
- не работает с финансами: не пополняет баланс, не управляет оплатой,
  не вызывает финансовые методы;
- не показывает рекламу и не взаимодействует с пользователями Яндекса;
- не является публичным сервисом с веб-интерфейсом — интерфейс
  предоставляет вызывающая сторона (ИИ-агент).

## 6. Пример результата работы

По итогам аудита формируется отчёт с диагнозами, отсортированными по
приоритету, например:

| Приоритет | Диагноз | Последствие |
|---|---|---|
| 100 | Расход есть, конверсий нет | оплаченные клики без заявок |
| 98 | Тексты объявлений превышают лимиты | объявления не показываются |
| 62 | Цена конверсии выше целевой | переплата за заявку |

Отчёт выгружается в XLSX с листами «Диагнозы», «Находки», «Не проверено»
и в текстовый чек-лист правок.

## 7. Обращение с данными

- Собираются только данные, доступные владельцу аккаунта, выдавшему токен.
- Данные не передаются третьим лицам и не публикуются.
- Токены хранятся локально; ведение журнала исключает запись токенов.
- По запросу владельца доступ отзывается удалением токена — приложение
  немедленно теряет доступ к аккаунту.
